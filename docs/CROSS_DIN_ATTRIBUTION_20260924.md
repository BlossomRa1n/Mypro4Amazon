# DIN 交互机制与本轮 cross 结果归因

本报告基于已封存的九组开发实验、训练 history、DIN 原论文和作者公开实现。只做本地证据分析，不连接服务器、不训练、不读取最终 test 标签、不改原 selection/plan。

## 结论

本轮证据支持在当前固定 epoch-3 协议下保留 raw cross：删除额外 cross 或改成归一化门控版本均降低开发表现。这不否定 DIN 的交互机制。DIN 历史注意力内部的交互在三个变体中始终保留；本轮改变的是额外的用户 ID 向量与商品向量乘积。

优先优化训练停止点，再研究 cross 结构。九组模型的 screen HR/NDCG 都在 epoch 1 达到三个已保存评估点中的最高值，之后训练 loss 继续下降，开发排序变差。原协议固定 epoch 3，因此本轮不能事后改选 epoch 1 或重新打开 confirm。下一轮应提前注册 checkpoint 选择规则。

## 1. 结果究竟说明什么

下表为三个 seed 的均值，全部使用 epoch-3 模型。同一 confirm 用户、同一候选池、相同初始化共同参数、顺序和负例已通过校验。

| 方案 | confirm HR@5 | 相对 raw 的 HR 差值 | 相对变化 | HR 差值的 97.5% CI |
|---|---:|---:|---:|---|
| raw | 4.159583% | — | — | — |
| normalized_gated | 3.927500% | -0.232083 个百分点 | -5.5795% | [-0.309167, -0.153745] 个百分点 |
| zero_cross | 4.000417% | -0.159167 个百分点 | -3.8265% | [-0.239589, -0.079583] 个百分点 |

两种改动的 confirm HR 区间完全低于零，三个 seed 的最终 screen/confirm HR/NDCG 差值均为负。可以说“在本轮固定模型、用户和评估条件下，raw 优于两个改动，有配对统计支持”；不能扩展为 raw 在所有数据、所有停止点或最终 test 上都更好。前一报告“不能证明 raw 优越性”的措辞应按后一种全局外推限制理解，不应掩盖本轮区间整体低于零这一事实。

区间按同一用户先跨三个 seed 平均差值，再对 80,000 用户 bootstrap 10,000 次，覆盖用户抽样波动；不是对全部可能训练 seed 的完整不确定性估计。

全部方案的 confirm pool_hit=12.1275%，即 80,000 人中 9,702 人至少有一个目标进入 75 候选。固定这批候选时，即便完美排序，HR@5 也不可能高于 12.1275%。raw 在已召回目标用户中的 HR@5 为 34.2988%，门控为 32.3851%，去 cross 为 32.9863%。因此低绝对 HR 有召回覆盖的限制，但三方案之间的差值来自排序与训练路径，不能归咎于不同召回候选。

## 2. DIN 的 cross 与我们的 cross

DIN §4.3 的核心是候选相关的兴趣提取：

`a_t = MLP(历史商品 h_t, 候选商品 q, 二者显式交互)`

`interest(q) = sum_t a_t * h_t`

候选是跑鞋时，跑步装备历史应得到较大权重；候选换成厨具，厨房商品历史应该更重要。同一用户因候选不同而产生不同的兴趣向量。历史和候选共用商品 embedding，交互两端处在共同表征空间。显式乘积、差值把匹配线索直接交给网络，减少完全依靠拼接后 MLP 学出乘法关系的负担。

论文用语为 “out product”；作者公开代码具体使用 `[q, h, q-h, q*h]`，其中 `*` 为逐元素乘法。不能将此实现误述为构建完整的 256×256 外积矩阵，也不能把整套 DIN 优于基线的结果当成每个乘积独立有效的消融证明。

作者早期 demo 还有顶部交互：`u_emb_i = hist_i`，其中 hist_i 是针对当前候选 attention 后的历史表示，再计算 `u_emb_i * i_emb`；这里变量名里的 user 是行为聚合表示，不是查用户 ID 表的向量。作者推荐的后续 DIEN 仓库中，DIN 基线则同时使用历史总和、`item * history_sum` 和 attention 输出，仍不能等同于用户 ID × 商品 ID。

我们的实现包含两处交互：

| 位置 | 实际输入 | 本轮是否改变 |
|---|---|---|
| DINAttentionLayer | 历史商品与候选商品的拼接、差值和逐元素乘积，另含 brand/时间/评分等 | 三组均保留 |
| 第五个 cross token | 独立用户 ID embedding `u` × 商品 embedding `v` | 本轮 raw/normalized_gated/zero_cross 的比较对象 |

代码定位：`code/model_ext.py:74`、`code/token_models.py:173`、`code/token_models.py:187`。所以 zero_cross 并未关闭 DIN 的全部交互。

另有一个真实差别：论文明确放弃 attention 权重 softmax 归一化以保留兴趣强度，而我们在 `model_ext.py:101` 使用 softmax。作者早期 Amazon demo 和推荐的 DIEN DIN 基线也使用 softmax，因此论文描述与公开实现必须区分；不能简单认定“用了 softmax 就实现错误”。这是三组共同设置，不能单独解释本轮组间差值；如验证，应作为独立的 attention 实验。

DIN 论文主要是 CTR/log-loss 与 AUC/GAUC，公开 Amazon 任务预测最后一次行为；我们是未来窗口、BPR 混合负例、75 候选上的 HR@5/NDCG@5。两者数字不能直接比较。作者 README 还更正过旧 demo 的 BatchNorm 结果，复现时应明确代码版本，不能照搬旧论文表格数值作为本项目预期。

## 3. 已证实的现象与待验证机制

### 3.1 最强证据是训练继续而开发排序退化

| 方案 | screen HR@5：epoch 1 | epoch 2 | epoch 3 | 训练 loss：epoch 1 → 3 |
|---|---:|---:|---:|---:|
| raw | 4.846667% | 4.381667% | 4.416667% | 0.201098 → 0.004726 |
| normalized_gated | 4.885000% | 4.420000% | 4.268333% | 0.205818 → 0.020384 |
| zero_cross | 4.836667% | 4.371667% | 4.188333% | 0.204870 → 0.020391 |

九组各自的 screen HR 和 NDCG 都在第 1 个已评估 epoch 最好；不能写成“后面每一步单调下降”，例如 raw 部分 seed 的 epoch 3 比 epoch 2 有回升。门控版 epoch 1 的平均 HR 还略高于 raw，只有 +0.038333 个百分点，此处是描述性发现，未做新接受检验、不能改选赢家。

这符合过拟合或训练目标与未来候选排序失配的特征。100k 训练用户只有 604,511 条 prefix 训练行，平均每人约 6.05 行；用户 ID embedding 为 256 维，存在记住训练前缀的风险。训练正负分数差继续拉大，并不保证真实未来商品在召回候选中升到前五。现有日志无法进一步唯一分离 ID 记忆、负例分布、embedding 漂移和 BatchNorm 动态。

目前训练池不含 V2 通道，而评估候选包含；统计也仍非严格逐前缀因果。它们是共同的目标/数据分布风险，不是已经证明导致某个 cross 变体落后的原因。

### 3.2 门控归一化改动同时改变三件事

本轮 embed_dim=token_dim=256、fusion=concat，所以 cross_proj=Identity，cross 分支没有 LayerNorm。忽略公共 type offset 时：

`raw = u ⊙ v`

`normalized_gated = 0.32 * g * ((u / ||u||) ⊙ (v / ||v||))`

其中 `g=sigmoid(logit)`，是模型全局共用的单个标量，不随用户、候选或历史位置改变；它不是 DIN 中对每条历史与当前候选分别计算的激活权重。在范数高于 eps 时，也可写成 raw 乘以样本相关系数 `0.32*g/(||u||*||v||)`。L2 归一化移除了此分支显式包含的模长因素，并改变梯度方向；原始 user/item token 仍存在，因此不是整个模型完全丢失模长信息。

0.32 只是旧初始尺度匹配假设，不能匹配全部样本和全部训练时点；初始 gate=0.05 又进一步压低分支输出和传回该路的梯度，可能改变模型先依赖哪些特征。后续 head 可以部分补偿固定缩放，故不能以“输出小”直接证明表达能力低。

实测最终 gate 为 0.666639、0.661146、0.702652，显然没有卡在 0.05。当前实验缺少 normalized-only 和 raw-gated 组，不能将负效应唯一归因于归一化、0.32 或门控；更不能归因于不存在的 cross LayerNorm。此前提出“小 gate 更稳定”的建议是待检验假设，本轮未通过，不应继续当作结论。

### 3.3 删除 raw 分支为何可能受损

`u⊙v` 给模型一条直接的用户—商品匹配通路，拼接 MLP 虽可学习非线性交互，但相同预算下不一定能同样容易恢复这条信号。本轮删槽重训变差支持保留该分支；不证明 DIN attention 内部乘积的独立贡献，也不证明其对冷用户的作用。

zero_cross 是在 type offset 相加后清零完整槽，并非只删乘积。type offset 是所有样本共用的常量，head 已有偏置和 BatchNorm，所以差异主要体现额外优化参数化，不能直接据此说丢失了重要用户信息。

现有 cross_token_norm 只测第一名 screen 用户的一个训练前缀商品，而且包含 type offset；不是全样本统计，不能拿它断言交互幅度整体正常或个性化信号消失。未来应分别记录乘积、offset 和输出贡献的分位数及梯度，使用固定的训练前缀诊断集。

### 3.4 旧轮没有已确认的门控收益

9/22 的门控相对 raw：test HR 差 +0.00105，95% CI [-0.00040,+0.00245125]，本来跨零；显著的比较是门控对 normalized-only。旧轮单 seed、小 base、20k/20k、BF16；本轮全量编码与召回底座、100k prefix 用户、三 seed、20k/80k、FP32。不能把两轮视作只增加评估人数的原封重跑，也不能断言方向改变是哪一个差别造成的。

## 4. 为什么冻结为 no_winner

“冻结”指先注册数据、checkpoint、门槛和分支，再按结果执行，不是永久禁止优化。晋级要求包括 screen HR 严格正向、screen NDCG 非负、三个 confirm seed HR 都正向、平均 HR 至少 +0.0005（+0.05 个百分点）、97.5% HR CI 下界 >0、confirm NDCG 非负。本轮两个挑战者六条都不满足，并非仅差一个严格门槛。

无赢家即保留 raw，跳过仅为晋级方案安排的全量训练和最终 test；17,296 人留给将来真正有开发证据的方案。看到结果后改 epoch、放宽阈值或用 test 继续挑模型，会让最终验收集合参与开发，失去原用途。下一轮可以新注册规则，但本轮 screen/confirm 已是开发信息，不能再称全新独立确认数据。

## 5. 优化建议与顺序

1. **优先：验证训练停止策略。** 保留 raw、当前负例与候选配置；下一轮提前规定 screen 选择最佳 checkpoint（主指标 HR、NDCG 与较早 epoch 的平局规则），所有 seed 使用同一规则。最多 3 epoch，先存最佳与 last，两套模型都锁定后才统一读 confirm；新收益需要配对 CI，不能拿本次 epoch 1 的 screen 数字直接宣称。本轮只有 last checkpoint，虽然保存了各 epoch 的 screen 数组，但不能据此补算未保存模型的早期 confirm；该验证需要下一轮重训。若停止策略稳定改善，再把它作为下一轮结构比较的共同基线。峰值早于 epoch 1 仍有可能，细化步数检查属于另一项提前注册的设置。
2. **若目的是查清旧改动为何失败：拆因素。** raw、normalized-only、raw-gated、normalized-gated 四组能区分归一化套餐与门控及其交互；0.32 需记录为归一化套餐的一部分，如要单独归因缩放还需额外对照。所有组固定相同停止/选择规则。不把归一化、gate、负例和 attention 一起修改。
3. **若目的是加强 DIN 风格交互：保留 raw，增加行为兴趣与候选的残差交互。** 例如 `c = u⊙v + α*(interest(v)⊙v)`，复用现有 attention 输出，让新支路直接描述“历史兴趣是否匹配当前商品”。α 使用可训练标量直接初始化为 0（不是 sigmoid(0)=0.5），并复制共同参数，可以保留原模型初始输出；不能把整个已有 cross 乘以 0.05。这是待验证方案，不保证胜过 raw；固定形状和独立初始化审计后再比较。
4. **之后单独处理目标分布与覆盖。** 检查真实候选中的负例来源、流行度和假负例；需要时使用严格截断或交叉拟合的召回器构建训练负例，不能直接拿包含该训练正例的已拟合召回器采样。召回覆盖 12.1275% 是另一条优化主线，固定精排后独立验证召回变化。论文式不归一化 attention、Dice、稀疏特征正则应各自作为独立假设，避免堆叠修改后无法归因。

建议下一次服务器实验只先验证第 1 项；其余保留为后续选项。本次没有新增训练、confirm 评估或最终 test。

## 6. 后续澄清：早期消融、停止点与 AUC/GAUC

### 6.1 “原始 cross 曾大幅降低结果”需要按轮次纠正

`raw` 就是原版额外 cross token：用户 ID embedding 与商品 embedding 逐元素相乘，然后加入公共 token 类型偏置。本轮没有增加 cross 投影（256→256 为 Identity），也不做 L2 归一化或 gate。`zero_cross` 将完整 cross 槽清零；DIN 历史注意力内部的交互始终保留。

9/21 旧消融确实出现 zero_cross 点估计高于 raw。为判断幅度，本次只读取原封存逐用户数组，核对 SHA-256 与原 manifest 一致，并验证成对 UID、position、pool_hit、人数与用户唯一性；不进行模型评分或读取新标签。使用 10,000 次用户配对 bootstrap、seed=20260924，得到以下探索性、未校正多重比较的 95% 区间：

| 9/21 切分 | raw HR@5 | zero_cross HR@5 | 去 cross 净增命中用户 | zero − raw 差值 | 95% CI（百分点） |
|---|---:|---:|---:|---:|---|
| screen，20,000 人 | 1.900% | 2.000% | +20 | +0.100 个百分点 | [-0.045, +0.245] |
| 旧 test，20,000 人 | 1.895% | 1.940% | +9 | +0.045 个百分点 | [-0.095, +0.185] |

因此用户对旧数字的记忆正确，但这轮不足以确认“原始 cross 大幅有害”。9/22 门控相对 raw 的旧 test 差值 +0.105 个百分点，95% CI [-0.040, +0.245125]，同样未确认收益；当时显著的是门控相对仅归一化版本。9/24 的三 seed、80k confirm 则在固定 epoch 3 下同时支持 raw 优于门控和删槽。前后轮次还改变了数据底座、召回资产和数值精度，不能把方向变化唯一归因于用户数或 seed 数增加。

上述旧 test 已参与开发判断，不能重新命名为 fresh holdout。配对复算回执：`server_snapshot/next_cross_20260924/followup_analysis/old_ablation_paired_20260924.json`。原实验报告、selection 和 plan 均未修改。

### 6.2 下一项建议：在合理停止点下重新比较 raw 与 zero

九组模型均在已评估的 epoch 1/2/3 中以 epoch 1 的 screen HR/NDCG 最好。epoch 1 三方案平均 HR 分别为 raw 4.846667%、门控 4.885000%、zero 4.836667%；这只是描述性统计，尚不能证明同样选择停止点后谁最好。最新结论应表述为“固定 epoch 3 下保留 raw”，不能扩大成跨停止策略的普遍架构结论。

建议下轮仅做 raw / zero_cross × 三 seed，共六次训练，同时回答停止点与 cross 两个问题。它是对上一节优先事项的具体化，不是本次启动授权或已完成实验：

1. 保持 100k 训练、20k screen、80k confirm、同一候选池、共同参数初始化、顺序和负例；最多三 epoch。运行前固定评估点，例如 0.25、0.5、1、2、3 epoch，并核算额外评估成本。每组保存 screen 最佳与 epoch-3 两份 checkpoint；HR 为主、NDCG 和较早评估点为依次平局规则。
2. 固定小型训练诊断面板与 screen 评估样本、负例，记录 train/dev 配对损失、AUC、候选 GAUC、HR/NDCG、embedding 范数、梯度和 BatchNorm 统计。线上累计训练 loss 的下降不能替代固定面板比较。
3. 所有模型和选择规则锁定后再统一读取 confirm。提前注册两个主要比较：best-raw − epoch3-raw（停止策略）、best-zero − best-raw（cross 在统一停止策略下的贡献），固定配对统计和多重比较控制；其余曲线只作诊断。同一模型保存两个 checkpoint 不需要额外重复训练。
4. 若固定 train 面板继续变好而 dev 配对损失/AUC 变差，优先检查过拟合并独立验证正则或 embedding 学习率；若 dev AUC 改善而候选 HR 下降，优先检查负例和 Top-5 目标失配；若评分随不相关的 batch 组成改变，先修评估或归一化路径。每种现象都是定位证据，仍须控制实验确认具体原因。

现有 confirm 已参与开发，重复使用属于开发复验，不能称为全新独立确认。17,296 人最终 test 继续封存。早停能否稳定改善 confirm、最优点是否早于 epoch 1，以及门控在合理停止点下是否占优，目前均未验证。本轮只有最后 checkpoint，不能仅凭早期 hit 数组补算早期模型的 confirm。

### 6.3 AUC/GAUC 应补充，HR/NDCG 仍作为 Top-5 主指标

新 runner `code/run_cross_multiseed.py:876` 只记录 HR@5、NDCG@5 和 pool_hit。任务与 DIN 论文不同意味着指标数值不能直接横比，不意味着 AUC/GAUC 不适用；本轮缺少它们，限制了训练退化归因。

当前旧 DIN 主评估路径 `code/train_din_ext.py:96`、`:190`、`:303` 使用每用户最后一个验证正例和 50 个未见随机负例；`code/baseline_runtime.py:72` 对同用户内正负分数比较，平分计 0.5，再按用户等权平均。这是采样版 user-AUC，在每人候选数相等时也等于按候选数加权的 GAUC；不是工业曝光日志上的 GAUC。函数注释中“不是标准 ROC AUC”不应照抄为数学事实：单正例时该配对计算与该用户候选集合上的 ROC AUC 等价。当前核查的代码与结果记录没有发现独立 GAUC 实现/输出，不能据此断言历史所有版本都没用过。

另一条遗留路径 `code/evaluate.py:483` 将各用户正负分数混在一起比较，负采样和 tie 处理也不同，不能与上述 user-AUC 混为一个统一历史口径。

下轮建议同时输出：全用户 HR@5/NDCG@5/pool_hit；固定随机负例上的 sampled user-AUC 用于诊断；真实 75 候选内的用户等权 GAUC 用于诊断候选排序。GAUC 需提前固定标签、权重、平分计 0.5、无正例或无负例用户的排除规则，并报告有效人数与覆盖率。本轮 confirm 只有 9,702/80,000 人的候选池含目标，因此候选 GAUC 只能覆盖其中同时有负例的用户，不能写成全用户效果，也不能靠注入正例改变实际 HR。未观测候选仍是假定负例，不是真实曝光未点击标签。

AUC 关注所有正负对，HR@5 关注前五是否命中；把目标从第 50 名提升到第 10 名能改善 AUC，却仍然 HR@5=0，所以二者互补。BPR 不限制 AUC 的使用，但其用户间分数偏移使混合跨用户 AUC 更难解释，用户内指标更贴近排序目的。已保存的 hit/ndcg/pool 数组缺少逐候选分数，无法事后还原 AUC；需要 checkpoint 重新评分或下一轮保存分数，本次没有进行这些操作。
