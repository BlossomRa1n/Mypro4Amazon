# 下一优先方向：用户 embedding 的相对学习率

日期：2026-09-25。本文为研究建议，不是执行协议；不新增实验、接受阈值或启动授权。

本轮 V2 训练池的三 seed confirm HR@5 平均差为 −0.08333 个百分点，四项注册门槛均未通过，保留旧训练池。唯一下一优先方向是：在旧池及 raw 架构下，研究降低 user_embedding 相对学习率。可讨论 0.1× 对现有 1× 的单因素比较，但 0.1× 只是待预注册的候选，尚未确定，也没有收益保证。

依据是训练动态而非因果定论。旧 raw 从 step591 到2362，固定训练正例面板的用户向量范数中位数由0.43079升至0.73031，原始用户×商品乘积由0.02882升至0.05920；这里均为三个 seed 各自中位数的均值。固定训练面板 BPR loss 同期由0.21659降至0.06856，而 screen HR 均值由0.05037降至0.04847。这提示优先检查拟合速度与开发排序之间的分歧。源码中同一用户向量同时进入 user_proj 和乘法 cross，再经可学习投影及类型偏置，故降用户表学习率会同时影响两条路径；交叉 token 范数变化不能直接归因于用户表，更不能证明“用户 ID 记忆”已被定位。

曝光也不是单独解释。seed43 新 best 提前至591，较旧1181少覆盖17,666名 confirm 用户；但同停点的 seed44 仍下降，seed43 已见与未见组也均下降。分组为事后描述，活动度、历史长度和停止选择均可能相关；未消费自身前缀不表示共享参数或用户参数完全未变化。

两分支各 seed 的首 epoch 都只有一次裁剪前梯度范数超过5，loss、梯度和保存张量均有限。各检查点 BN 计数等于更新步数，固定8用户的候选批次不变性检查均通过。这降低了明显数值爆炸或观测污染的嫌疑，却不能排除 BN 统计分布偏移、优化目标失配或正常有限更新造成的过拟合。

暂不继续 cross 结构搜索，因为它会同时改变表示能力与交互尺度，难以回答当前的更新速度问题。也不盲加 V2 或加大 hard-negative 配额：本次改池已使两个采样区间约47.91%及44.47%的行改变成员，仍未晋级；新增候选不等于更难、V2独占或更少假负例。先研究更窄的优化干预，更便于解释后续差异。

未来必要控制是：两臂同旧池、合法行与顺序、seed/初始化、SVD商品初始化、负例算法和负例流、batch、精度、更新预算、共同 screen 网格和选模规则；仅用户参数组按预注册倍率变化，其余组及调度路径不变。AdamW 的 lr 同时影响梯度更新和衰减幅度，必须先声明比较的是“用户组学习率策略”，不能把结果称为纯梯度速度效应，也不能暗调 weight decay 补偿。可预先记录分组实际更新量、范数、BN统计及同步数曝光，用于区分线索，不追加择优门槛；改善仍不能拆分直接用户路径与 cross 的贡献。

旧控制只有在参数分组后的1×实现与冻结控制证明数值等价、来源及全部共同合同吻合时才可复用；无法证明、改变预算或迁移全量时，应预注册并重训匹配控制。不得用新 fast 指标与旧 full 指标直接声称收益。confirm 仍为重复使用的开发数据；旧 test 可在未来明确方案中作为已曝光 benchmark，结果须如实标注。重训控制或重切已看用户都不恢复 test 新鲜性，新的最终泛化验收需要未参与开发选择的新评价数据。本轮未彻底解决因果问题。
