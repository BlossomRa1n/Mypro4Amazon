# 项目交接与下一步计划

更新时间：2026-09-14（Asia/Shanghai）

## 当前项目

这是一个基于 Amazon Reviews 2023 五个品类的“召回 + 精排”推荐系统，目标是为用户输出 Top-5 商品。当前代码同时保留历史实验和一套修复后的可复现基线，不能混用两套结果。

权威基线入口是 `code/run_baseline.py`。它修复了训练目标泄漏、训练集外 SVD/统计、PAD/UNK 编码、完整已见历史过滤、候选去重回填、断点恢复和指标计算等问题。相关协议见 `docs/BASELINE_PROTOCOL.md`。

## 已完成结果

- 修复版基线已在服务器完成，单目标 leave-two-out 测试用户 100000 人的 HR@5 为 2.081%。
- 最终已选方案为：原 SASRec 双塔 + 随机负样本 DIN 续训 + RRF 四路融合 + ItemCF 90 天衰减 + 100 候选。
- 单目标测试 HR@5 为 2.433%，相对基线提高 16.92%；候选命中后的 DIN Top-5 成功率约 29.94%。
- 候选预算 100/200/300、随机与混合难负样本、额外 SASRec 训练、结构消融、RRF 和品牌通道均已做过筛选。当前混合难负样本和结构改动未入选。
- 服务器与本地测试累计 22 项通过；模型包、最终测试、保留验证和效率结果已同步到 `server_snapshot/2026-09-12/final_optimization_20260912/`。
- 服务器没有正在运行的训练进程，GPU 空闲。系统盘约 6.9 GiB、数据盘约 8 GiB 可用；此前已清理重复 checkpoint 约 17.97 GiB。

## 指标调整

业务目标是“未来窗口内 Top-5 准确率”，因此主指标应改为未来窗口 HR@5：每个用户按时间取前 80% 正反馈作为历史，后 20% 的所有唯一正反馈商品作为目标集合，Top-5 命中任意目标即成功。单目标 leave-two-out HR@5/NDCG@5 继续作为辅助诊断。

`code/future_window_data.py` 已修正为真正调用 80/20 切分，相关测试已通过。当前服务器只完成了该入口的兼容性测试，还没有用最终模型正式跑完 10 万用户未来窗口主指标。

## 下一步

1. 用服务器最终模型跑未来窗口评估小样本，核对 80/20 边界、目标集合、已见过滤和 Top-5 统计。
2. 扩大到 100000 用户，分别输出基线和最终方案的主指标，同时保留单目标辅助指标。
3. 按候选覆盖率与候选命中后的排序成功率拆解瓶颈，分品类、历史长度、商品热度输出分组指标。
4. 若覆盖率低，优先优化召回融合；若覆盖率足够但 Top-5 低，优先优化 DIN 训练目标和候选负样本。
5. 只有在未来窗口主指标稳定后，才继续做 token/raw-slice、RankMixer、MIND/HSTU 或学习式融合；每次只改变一个因素。
6. 结果确认后更新工作汇报，下载必要产物并清理服务器中间文件。除非用户另行要求，不自动关机。
