# 召回与精排优化最终报告

日期：2026-09-13。最终实验于北京时间 02:27 完成；本地验收与关机状态以本文收尾记录及 `optimization_state_20260912.json` 为准。

## 结论

本轮采用 **原 SASRec 双塔 + 随机负样本续训 DIN + RRF 四路融合 + ItemCF 查询历史 90 天半衰期衰减 + 100 候选**。品牌补充通道、精排结构改动及召回负样本训练未入选。

最终 100000 测试用户上，HR@5 从 **2.081% 提升到 2.433%**，绝对提高 0.352 个百分点，相对提高 **16.92%**。NDCG@5 从 **1.3485% 提升到 1.5855%**，相对提高约 **17.58%**。不是相对历史旧协议的提升。

配对 bootstrap 的 HR@5 差值 95% 区间为 `[+0.272, +0.432]` 个百分点；975 个用户从未命中变为命中，623 个用户反向变化，净增加 352 个命中用户。方案在查看测试结果之前已确定，未依据测试结果重新调参。

## 指标口径

本轮采用用户内下一次正反馈任务：rating >= 4，用户与商品重复正反馈保留最早一次；有资格用户倒数第二个目标用于验证，最后一个目标用于测试。每次输入仅包含目标之前的历史。目录约 37.9 万商品，固定全库 Top-100 召回，再输出 Top-5。

| 评估集合 | 修复基线 HR@5 | 最终方案 HR@5 | 修复基线 NDCG@5 | 最终方案 NDCG@5 |
| --- | ---: | ---: | ---: | ---: |
| 未参与开发的验证用户 100000 人 | 2.501% | 3.048% | 1.6039% | 1.9805% |
| 最终测试用户 100000 人 | 2.081% | 2.433% | 1.3485% | 1.5855% |

留出验证净增 547 个命中用户，HR@5 差值 95% 区间 `[+0.461, +0.634]` 个百分点，一次验收通过。开发期使用前 10000 用户初筛、随后 90000 用户确认；保留验证取确定性用户序列 `[100000:200000]`。这些集合数值不能互相替代。测试包含用户的新事件，不是全新的冷启动用户实验。

测试候选覆盖率从 8.443% 降至 8.125%，但候选命中后的 Top-5 成功率从 24.65% 提升到 29.94%。最终提升不能归因为候选覆盖增加。品牌未入选，未声称本轮学习了四路融合权重。

## 双塔为何从 10% 变为约 5%

**旧指标可以保留，并非必须改用现在的指标。**修复数据正确性和改变业务评估任务是两件事。此前将它们合并描述不够清楚。

- 旧协议按用户 80/20 切分，把后 20% 的多个正反馈商品组成目标集合。Top-100 命中其中任意一件，该用户 HR 记为 1。
- 本轮协议每个验证用户只有一个指定后续目标，必须命中该目标才记为 1。
- 例如未来正反馈为 C、D、E，而 Top-100 只有 E：旧多目标 HR 算成功；下一件指定为 C 的单目标 HR 算失败。两者都检索全库，但任务、历史、用户资格和目标集合不同。
- 原 Phase 2 的验证 HR@100 10.13% 与本轮 100000 用户的 4.886% 不能直接判断为能力减半。当前双塔测试 HR@100 为 4.086%。
- 旧服务器 `train_v2.py:238` 将完整交互传给 SVD 初始化，存在验证交互进入初始化的代码路径；具体 Phase 2 缓存是否污染仍需追溯生成过程。不能把旧成绩全归因为泄漏。
- 新训练还改变了去重、前缀历史、统计特征及负采样。旧训练目标可出现在完整训练历史中是任务错配，但不等于验证历史直接包含验证标签。各因素对分数的贡献未做逐项归因。

新双塔在同一 10000 初筛用户上三轮 HR@100 为 3.37%、4.15%、4.88%，续训两轮为 5.05%、5.06%。单路点估计仍在改善；没有采用续训版本，是因为固定 DIN 后端到端收益未通过确认，而非证明双塔达到上限。

对于“推荐未来可能喜欢的 Top-5”，未来窗口多目标评估同样合理，可以作为后续主任务；同时报告 HR、Recall 和规范化 NDCG，避免 HR 只反映“至少命中一件”。下一次单目标任务可保留为辅助评估。恢复多目标任务需要固定用户、切分、已见过滤和目标资格，再重训或明确标为跨任务诊断；不能拿旧 10.13% 与本轮数字直接拼表。此次保留完整单目标实验，不在测试之后改动任务来追求更高分数。

## 效率与限制

最终模型的 1024 用户、每用户 100 候选、预热后三次测量：参考精排中位数 0.9259 秒，缓存路径 0.8144 秒，吞吐提高 **13.70%**，耗时减少约 **12.05%**，完整排序一致。这是批量精排性能，不含召回、网络及服务排队，不是在线单请求延迟。前期 11.7% 来自另一批次测量。

- 模型约 3.15 亿参数，最终仍保留大规模用户 ID embedding；删 ID 本轮未入选，不能声称实现了模型压缩。
- 全局平均提高不代表每个品类提高。测试 Musical_Instruments 的 HR@5 从 2.3806% 降至 1.9838%；留待独立开发数据上研究，不依据本次测试进行修补。
- 冷商品和长尾仍弱：测试训练期未出现目标的 533 用户未命中。冷启动、内容特征及互补召回值得后续研究。
- 这是用户内时序评估，目录 ID 预先可知，静态品牌/品类可用性作假设；不是全局时间截断部署回测。
- 原始数据是正向评论，不能把预测分数称为经过校准的购买概率；没有曝光日志，未交互负样本不等于真实拒绝。
- Mixer/MoE 暂缓：继续训练对照损失极低且验证下降，没有足够证据优先增加容量。这不证明此类结构无效。
- 标准 HSTU/MIND 重训、含内部 SASRec 特征的四路学习融合、双塔新旧指标的逐因素归因均属于后续研究，本轮未完成，也不作为本次关机前的未交付实验。
