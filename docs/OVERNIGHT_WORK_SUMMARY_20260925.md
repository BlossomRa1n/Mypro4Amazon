## 已得到的结论

1. **开发集上的训练退化已有可执行的处理办法：按预注册 screen 规则保留早期 checkpoint。** 三个 seed 的固定 80,000 人 confirm 平均 HR@5 从 epoch3 的 4.159583% 提升到早期 checkpoint 的 4.687083%，增加 0.5275 个百分点，95% 配对区间为 [+0.442083, +0.612083] 个百分点。所有注册开发支持条件通过，因此停止继续搜索新的退化优化。
2. **cross 消融已在共同早停条件下重做，保留原始 raw cross。** 去 cross 的 HR@5 均值只高 0.0041667 个百分点，97.5% 区间为 [−0.045000, +0.052917] 个百分点；三个 seed 一正两负，未通过晋级标准。这既不证明两个模型等价，也不证明早期 raw 显著更好。
3. **100,000 人最终 test 的人数问题已解决。** 对本月早期 Stage A/B 的实际评估身份作确定性重建，保留其他排除来源和最新 screen/confirm 后，有 337,749 名合格用户。提前固定抽取 100,000 人，未按模型效果或未来商品内容选人；六月实验按用户批准不作为排除条件。原始逐次名单未保存，恢复依据及局限见身份审计。
4. **锁定 raw 模型的最终 test：HR@5 为 4.520%，NDCG@5 为 0.02047114。** 75 个候选至少命中一个未来正例的用户比例为 11.871%。候选 GAUC 为 0.802132，仅覆盖候选内同时有正负例的 11,871 名用户；不能解释为全用户或全 catalog GAUC。最终只评估这一模型，没有全量三轮或去 cross 的最终对照。

## 为什么不继续无限优化

诊断观察到训练拟合持续增强，而未来排序在早期以后下降。已有探针和日志没有发现记录范围内的数值崩溃；用户 ID 记忆、共享表征漂移及训练与评估负例分布不一致仍可能同时存在，没有被本轮独立因果拆分。

用户批准可以在判断已有有效处理办法时停止，并要求总结证据。早停已提供避免部署较差 checkpoint 的方法，因此不为用满额度而追加调参。窗口固定为北京时间 2026-09-25 00:04:49–08:04:49，最多三轮新优化，实际只新增一轮共同早停下的 cross 复验。截止后不启动新轮，已开始的注册范围按原规则完成。

confirm 已参与开发判断。上述配对区间先在每名用户内对固定三个 seed 求平均，再按 80,000 名用户重采样；不是 240,000 个独立样本，也不覆盖任意训练 seed 的不确定性。

旧固定 epoch3 下 raw 优于 zero_cross 的结果没有被改写。新复验改变的是停止策略；不同停止条件下的结构差可以不同，不能由“旧区间不跨零、新区间跨零”直接推导交互显著。详细分析见 `OVERNIGHT_CROSS_RESULTS_20260925.md`。

## 全量与最终 test 合同

最终只验收一个锁定模型：semantic_concat、随机用户初始化、SVD 商品初始化、raw cross；seed42、init424242，FP32，batch256，BPR mixed16。全部 4,731,777 条合法历史 prefix 行完整训练一遍，共 18,484 次更新，最后一个 batch 为 129 条。学习率、AdamW 和 Cosine T_max=3 保持原合同。

快速开发训练 100k 等于 screen20k 与 confirm80k 的用户并集，但只训练各用户合法历史；最终 test100k 与开发用户隔离。全量训练允许使用 test 用户在评估边界之前的合法历史，并要求实际训练记录覆盖全部 test 用户。它不允许提前读取这些用户的未来目标。

训练候选仍用权重 [2,0,0.7,0.05]，最终评估候选用 [2,1,0.7,0.05]；RRF、75 候选、ItemCF300、180 天半衰期保持不变。训练候选没有 V2 通道这一差异仍然存在，本轮没有通过最终 test 再修改它。

身份隔离不等于全部特征都满足严格时序因果。当前仍复用完整合法 prefix 聚合统计、SVD、ItemCF、V2 资产及完整 prefix 的负例排除，并采用静态 catalog 假设；没有保证这些信息在每条训练记录当时或统一全球日历时点都已可得。协议的 strict_per_row_causal 与 strict_global_calendar_causal 均为 false，最终指标必须保留这一适用边界。

全量一遍是为覆盖全部合法历史而预先固定的规模迁移选择，不是快速开发 0.25/0.5 epoch 的完全相同处理。没有 full3 或最终 zero_cross 对照，因此最终 test 只报告 raw 的绝对指标，不能据其声称全量一遍优于三遍，或证明 cross 的最终收益。

本轮 structure_gain_accepted=null、business_threshold_registered=false，不能将完整执行写成结构收益或业务达标。候选 GAUC 仅在候选内同时有正负例的用户上计算，并与有效人数、覆盖率共同报告。
