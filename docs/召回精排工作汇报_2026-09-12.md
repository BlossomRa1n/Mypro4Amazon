## 一、项目概述

两阶段推荐系统：**多路召回 → DIN 精排 → Top-5 提交**。基于 Amazon Reviews 2023 benchmark（5 品类：Musical_Instruments / Office_Products / CDs_and_Vinyl / Video_Games / Toys_and_Games），约 797 万正反馈交互、83.1 万用户、37.9 万物品。

核心指标：召回 **全库 HR@100**，精排 **全库 HR@5**（评估协议：10 万采样 val 用户 seed42 + 全库 HR@5，定稿时上全量）。

## 三、精排进展

### 3.1 基线 DINExtendedModel
- **val AUC = 0.7417**（epoch1 峰值），379K 真实物品空间重训验证
- 结构：flat concat 1358 维 = user(256) + item(256) + cat(256) + brand(64) + verified(4) + DIN interest(256) + dense(10 标量) + interaction(user⊙item, 256)
- **HR@5**：单路 0.719% / **并集池 1.306%（+82% 相对）**——验证纯并集合并兑现召回独有命中，**精排是当前瓶颈**

### 3.2 token 化重构（DINTokenizedModel）——塌缩排查与反转
**动机**：flat concat「一锅粥」→ 5 个语义 token（每 token 单一数据源），为 RankMixer/Perceiver/MoE 铺路。

**塌缩排查（3a 三连消融）**：
| 实验 | 改动 | val AUC | 结论 |
|---|---|---|---|
| 初始 | 五路 token（含 cross⊙ctx 二次项 + item 加权求和） | 0.5105 | 塌缩 |
| 修复 1 | 删 cross_out LayerNorm | 0.5364 | 必要非充分 |
| 3a-1 | 关 user warm-start | 0.5359 | user warm-start 排除 |
| 3a-2 | 去全部 LayerNorm | 0.5502 | LayerNorm 排除 |
| 3a-3 | item token 拆分（删加权求和/二次项，item_emb raw 直连） | **0.6745** | **item 加权求和/二次项是主凶** |

**根因结论**：SVD warm-start 的 item_emb 先被随机 `item_core_proj` 打乱、再和 `core⊙ctx` 二次项、`w1/w2/w3` 加权求和搅在一起 → CF 信号被搅碎。残余 -0.067（vs 基线 0.7417）来自 token 定义处的 `user_proj`(256→256)/`item_ctx_proj`(336→256) 继续打乱 raw 信号。

**方向反转**：不放弃 token 化（面试叙事 + RankMixer/MoE 地基需要），改走 **raw-slice token 无损拉回基线**路线（见 3.4）。

### 3.3 负样本优化（Stage A/B）
- **Stage A（负样本①）——「用户塔算一次，对 N 个负样本打分」**：
  - 4 处改动：Dataset 打包 `(uid, pid, [neg×4])` / `__getitem__` 负样本堆叠 (K,) / 模型新增 `_encode_user` + `_score_item` + `forward_bpr` / 训练循环切换
  - 加速 1.6×（5 次 item score 替代 8 次），数值对拍通过（pos_err=0，neg_err=3.7e-8）
  - 首挂崩溃（`train_din_ext.py:510` pair-accuracy 广播 bug，补丁漏改下游指标行）→ 修复 → 重挂 → **已跑完**（服务器自动关机已触发，结果待读）
- **Stage B（负样本②）——DIN_NEG_RATIO 4→8**：
  - 原设计 in-batch（InfoNCE 矩阵）对 DIN 不可行（逐 (user,item) 对 attention 成本 ~100×），修订为简单加负样本数
  - 已挂在自动关机链条中（Stage A 正常完成后自动启动）→ **结果待读**

### 3.4 token 化保留 + 逐步验证方案（6 步，已定稿）
| Step | 改动 | 目标 | Gate |
|---|---|---|---|
| 1 | **raw-slice token**：删全部投影（user_proj/item_ctx_proj/dense_mlp），token = 语义切片 raw 直连 | 回基线 AUC≈0.7417 | <0.72 → Rung0 二分定位 |
| 2 | user warm-start 正确版（U·Σ 不 L2 归一化，保留活跃度） | +δ | 不涨回退 |
| 3 | cat embedding 256→16（44 品类 256d 约 50× 冗余） | 不降反升 | HR@5<0.719% 回退 |
| 4 | dense 标准化 + log 长尾变换 | 正则 +δ | 回退 |
| 5 | **RankMixer**：per-token Linear→统一 256 + token 间 self-attention → pool → MLP | **超基线（真正增益点）** | — |
| 6 | 稀疏 MoE（按 token 类型路由，可选） | 超 RankMixer | 风险最高 |

**三条原则**：(1) 每步一个变量、可归因；(2) **投影放在 mixer 层、不在 token 定义层**（token 是自然宽度 raw 切片，统一宽度/交互在 RankMixer 里做）；(3) 快速 gate 用 10 万 val AUC，关键 gate 用 10 万 HR@5。

**关键架构教训**：token 化失败不是 token 化的错，是「在 token 定义处投影压缩打乱 raw 信号」的错；正确姿势是「语义切片 + 在 mixer 里投影到统一空间」。Step 1 token 化本身是等价重构（对齐基线、不期望超），真正超基线的是 Step 5 RankMixer。

## 七、2026-09-19 未来窗口正式验证补充

为使业务目标与评估一致，正式主指标已切换为未来窗口 Top-5：每个用户前 80% 的正反馈作为历史，后 20% 的所有唯一正反馈商品作为目标集合，Top-5 命中任意目标即成功。旧 leave-two-out 数字保留为辅助诊断，不与本节结果直接比较。

服务器正式基线和 RRF 对照均使用五品类全量数据、固定 seed=42、100,000 个测试用户、100,000 个开发用户、3 epoch、256 维模型。基线测试结果为 DIN HR@5 `3.468%`、NDCG@5 `1.5404%`、候选池 HR@100 `13.132%`。RRF + ItemCF 90 天半衰期先在同一 100,000 开发用户上验证：DIN HR@5 `3.556% -> 4.029%`，NDCG@5 `1.5748% -> 1.7936%`，配对差异 `+0.473` 个百分点，严格门控通过后才运行测试集。

最终测试结果：DIN HR@5 `3.842%`、NDCG@5 `1.7056%`、Recall@5 `2.2397%`，候选池 HR@100 `12.275%`，候选命中条件下 DIN HR@5 `31.30%`。相对同一未来窗口基线，HR@5 提升 `0.374` 个百分点（约 `10.79%`），NDCG@5 提升约 `10.73%`。结果、预测、监控状态和运行身份已归档到本项目 `server_snapshot/2026-09-19/`。

结论：当前主要瓶颈仍在候选覆盖率；RRF/时间衰减提高了精排最终命中，但候选池 HR@100 仍约 12%，后续优先做召回预算、ItemCF 衰减和融合权重的单变量开发集筛选。精排结构改动必须重新训练并遵守同一未来窗口协议，不能从旧 leave-two-out checkpoint 推断主指标收益。
